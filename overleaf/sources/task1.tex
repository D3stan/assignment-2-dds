\section{Task 1: Design and Implementation of the Sobel Accelerator} \label{sec:task1}

Throughout this section, we will detail the design decisions that led to the final implementation. 

\subsection{Initial Design}

First, we explain the initial design choices; detailing the functionalities of each component; i.e., the address incrementer, cache, decoder, ALUs and FSM; subsequently, we detail how these components interact with each other.

\subsubsection{Cache}

To store computation data, we make use of a 3$\times$88 word register matrix. Assuming that the images have a width of 352 byte sized pixels, 88 words store exactly one row ($352/4=88$).

The cache is organized into three horizontal register lines as follows:
\begin{itemize}
    \item the bottom line receives an incoming 32-bit word directly from the input buffer. When the fetch enable signal is asserted, the line selects the register corresponding to the fetch position signal (thanks to a 7-to-88 binary decoder), and stores such word into the selected register.
    \item The middle and top lines operate as parallel shift registers across the vertical axis. When the shift enabled signal is asserted, the entire bottom line is transferred to the middle, whereas the content of the middle line shifts to the top line.
\end{itemize}

\subsubsection{Address Incrementer}

The address incrementer is the sequential component responsible for handling the read and write pointers (internally stored as two-dimensional indices) and generating boundary status flags for the FSM. To process the $352\times288$ byte ($88\times288$ words) image, the module tracks two independent coordinate pairs: the row and column indices for both the input and output buffers (\texttt{rd\_row, rd\_col, wr\_row, wr\_col}).

\paragraph{Pointer Management.} The module receives four input signals to control the address pointers: two for incrementing read and write column indices (\texttt{rd\_inc, wr\_inc}), and two to advance to the next row (\texttt{rd\_wrap, wr\_wrap}). When an increment signal is asserted, the corresponding column index advances across the row from $0$ to $87$ for the write index and from $0$ to $88$ for the read index; if an increment signal is asserted when a column index has already reached the boundary value, such index wont advance further. Upon asserting a wrapping signal, the corresponding column index resets to $0$ while the row index increments.

\paragraph{Address Generation.} Linear word addresses are computed combinationally via the following simple formula
$$\text{addr} = \text{row} \times 88 + \text{col}$$ 
To avoid synthesizing hardware multipliers, which are expensive, the multiplication by $88$ is decomposed into shift and add operations using the identity $88 = 2^{3}\cdot(2^3+2^1+2^0)$:
$$\texttt{addr} = \bigl( (\texttt{row} \ll 3) + (\texttt{row} \ll 1) + \texttt{row} \bigr) \ll 3 + \texttt{col}$$
    
\paragraph{Boundary Flags.} The module asserts a series of flags to inform the FSM about the occurrence of certain events:
\begin{itemize}
    \item if the read column index exits the bounds of the image (\texttt{rd\_col=88}), the module asserts the \texttt{rd\_row\_end} signal;
    \item if the write column index reaches the image bounds (\texttt{wr\_row\_end=87}), the incrementer asserts the \texttt{wr\_row\_end};
    \item finally, if the write address reaches the last row (\texttt{wr\_row=287}), \texttt{wr\_col\_end} is asserted.
\end{itemize}

\subsubsection{Sobel ALUs}

To compute a full word-sized output per cycle, the system uses a set of four purely combinational \texttt{sobel\_alu} modules operating in parallel. Each ALU receives a $3\times3$ neighborhood ($p_{ij}$) of pixels and produces one output pixel.

Instead of computing the exact Euclidean gradient magnitude, which requires complex square root circuits, each ALU approximates the edge strength using $L_1$ norm $|D_x| + |D_y|$:
\begin{align*}
    D_x &= (p_{02} + 2p_{12} + p_{22}) - (p_{00} + 2p_{10} + p_{20}) \\
    D_y &= (p_{00} + 2p_{01} + p_{02}) - (p_{20} + 2p_{21} + p_{22})
\end{align*}
where multiplications by $2$ are implemented as inexpensive left shifts. The positive and negative terms of each gradient are summed into 10-bit unsigned intermediates, and their absolute values are obtained by comparing the two terms and subtracting the smaller from the larger.  
Finally, $|D_x|$ and $|D_y|$ are added into an 11-bit sum and clamped into the 8-bit range $[0,255]$ by checking whether any of the upper three bits are asserted.

\subsubsection{Pixel Decoder}

The pixel decoder is a  purely combinational module that , given the three full cache lines and the current write coordinates, extracts four overlapping $3\times3$ pixel windows corresponding to the four pixels within the target output word, handling eventual boundary conditions. 

To prevent out-of-bounds memory accesses along image edges, the decoder implements border replication.
\begin{itemize}
    \item On the first row, the upper line is substituted with the central row; similarly, on the bottom row, the lower line is replaced with the central row.

    \item For each of the three rows, the decoder selects the 4-pixel target word at the current column index and prepends the rightmost pixel of the previous word alongside the leftmost pixel of the subsequent word, creating a 6-pixel horizontal strip. When the focus is at the left or right boundary of the image, the outermost pixel of the current word is duplicated in place of the adjacent word.
\end{itemize}

\subsubsection{Finite State Machine}

The whole system is handled by a hybrid Mealy/Moore finite state machine (FSM); this module has the duty of managing all the other components in the accelerator. Initially, the FSM is supposed to be in the \texttt{IDLE} state. Once the \texttt{start} signal is asserted, the machine enters the \texttt{FETCH} state; here, it loads the first row of the image into the cache. Subsequently, the system enters the \texttt{SHIFT} state, which performs an upward shift in the cache; once the shift is completed, the fsm performs a series of 3 cycles (\texttt{WAIT\_0}, \texttt{WAIT\_1}, and \texttt{WAIT\_2}): 
\begin{itemize}
    \item the first asserts the \texttt{rd\_en} signal, requesting the next word from memory;
    \item the second inserts the received data into the cache (while asking for the second word);
    \item the third fetches the second word into cache.
\end{itemize}
Now the accelerator enters the \texttt{COMPUTE} state; where it computes one output word per cycle (four bytes at a time) and tells the address incrementer to advance read and write column indices; such process is repeated until the row ends. The accelerator must therefore pre-fetch two words before starting the computation since the last byte of the output word depends on the first byte of the second bottom word. Once the entire row has been computed (\texttt{wr\_row\_end=1}); the address incrementer moves the read and write pointers to the next row (\texttt{wr\_wrap=1} and \texttt{rd\_wrap=1}), and the cache performs an upward shift (by moving to \texttt{SHIFT}); the system then restarts from state \texttt{WAIT\_0}. This loop continues until the entire image has been filtered (\texttt{wr\_row\_end=1} and \texttt{wr\_col\_end=1}); here, \texttt{finish} is asserted, and the state machine goes back to \texttt{IDLE}.

\paragraph{Implementation Details.}

To maintain visual clarity in the state diagram (Figure~\ref{fig:fsm}), we omitted the output signals \texttt{rd\_en} and \texttt{wr\_en}. Such signals are derived combinationally: \texttt{wr\_en} directly mirrors the internal flag \texttt{wr\_inc}, asserting exclusively during the \texttt{COMPUTE} state; on the contrary, \texttt{rd\_en} is driven by \texttt{rd\_inc} across fetching, waiting, and compute states, but gated off during row boundaries or complete frame termination, that is
$$\texttt{rd\_en} = \texttt{rd\_inc} \;\wedge\; \neg(\texttt{rd\_row\_end} \;\vee\; \texttt{wr\_col\_end})$$

\subsection{System Structure}

Figure~\ref{fig:sys_struct} illustrates the top-level architecture of the initial accelerator and its external interfaces to the input and output buffers.

\paragraph{FSM Controller.} 

The FSM serves as the controller module, receiving the \texttt{start} signal and asserting the \texttt{finish} signal once the image has been processed. It coordinates memory operations by controlling the read and write flags (\texttt{rd\_en, wr\_en}), respectively, for the input and output buffers. Such signals, together with the wrapping flags (\texttt{rd\_en, wr\_wrap}), are used to drive the address incrementer; which, exchanges the relative boundary handling flags (\texttt{rd\_row\_end, wr\_row\_end, wr\_col\_end}). Additionally, the FSM controls vertical cache updates via the \texttt{shift\_en} signal and cache fetching via \texttt{rd\_en}.
    
\paragraph{Memory Synchronization.} 

Due to the input buffer read latency of one-cycle, a word requested at cycle $t$ will be available to the accelerator at cycle $t+1$. To ensure that the cache correctly stores incoming data into the exact column slot, both the fetch signal (\texttt{fetch\_en}, derived from \texttt{rd\_en}) and the column index (\texttt{fetch\_pos}, driven by \texttt{rd\_col}) are delayed by one clock cycle thanks to dedicated flip-flops.

\paragraph{Datapath.} 

Incoming words from the input buffer are written into the bottom line of the cache at the registered fetch position. The cache exposes its three full horizontal lines combinationally to the pixel decoder, which also receives the current write coordinates (\texttt{wr\_row} and \texttt{wr\_col}) from the address incrementer. From this data, the decoder extracts four overlapping $3\times3$ pixel windows and dispatches them to the four ALUs. Finally, the four output pixels are concatenated into a single word and written to the output buffer at the current write address (\texttt{wr\_addr}).

\subsection{Design Optimizations}

In the current state, the decoder is one of the most resource-intensive modules. The reason behind this stems from the immense number of inputs to this component, which corresponds to the size of the entire cache. The optimization we will implement, therefore, will aim at reducing the number of resources synthesized by developing a rotating cache design. Instead of scanning the cache linearly, this new system will only observe a fixed window, while the data will rotate in the opposite direction.

\subsubsection{Cache}

 The redesigned cache operates as a two-dimensional cyclic shift-register matrix. The cache now supports two independent shifting axes controlled by the FSM: vertical shifts between rows and horizontal leftward circular rotations along each row.

The three horizontal register lines operate as follows:
\begin{itemize}
    \item On both the upper lines, when the vertical shift signal is asserted, each register loads the word directly below it. When the horizontal rotation is asserted, each register $i$ samples its right cyclic neighbor $(i+1)\mod 87$, without discarding any value.
    \item On the bottom line, incoming words from the input buffer are no longer routed to all 88 columns; conversely, only the first two registers are capable of sampling the input word. A compact 2-bit control signal (\texttt{fetch\_pos}) directly governs writes into the bottom row:
    \begin{itemize}
        \item \texttt{fetch\_pos = 01} writes \texttt{in\_word} into register $0$;
        \item \texttt{fetch\_pos = 10} writes \texttt{in\_word} into register $1$;
        \item whereas, \texttt{fetch\_pos = 00} and \texttt{11} disable external writes.
    \end{itemize}
\end{itemize}

\subsubsection{Decoder}

The new decoder design simplifies the existing component: it does not receive the entire cache as input; on the contrary, it requires a small window of 6$\times$3 words. Such window corresponds to the first 5 columns of the cache plus the last as the further left one.

\subsection{FSM}

The new FSM design must output both the horizontal cache shift (\texttt{xshift}) and the cache fetch position (\texttt{fetch}). During the \texttt{FETCH} state, the accelerator fetches the input word into slot 0 of the cache and performs a horizontal shift (\texttt{fetch\_int=01, xshift=1}). After the \texttt{FETCH} state, a new state occurs (the \texttt{ALIGN} state); here, one cycle is used to perform a final horizontal rotation of the cache, needed to align the first word of the row with the first word of the cache. % WHY THIS HAPPENS 
The following state flow remains unchanged; whereas, the state outputs are modified as follows. \texttt{WAIT\_0} asserts \texttt{fetch\_int} to 01, while \texttt{WAIT\_1} and \texttt{WAIT\_2} assert \texttt{fetch\_int} to 10; finally, \texttt{COMPUTE} keeps fetching words from slot 1 of the cache (\texttt{fetch\_int=10}) while, at the same time, shifting the cache data horizontally.

This new design internally handles the "off by one cycle" delay and the boundary conditions of the cache fetching mechanism. That is, the output signal \texttt{fetch} is the sequential result of the \texttt{fetch\_int} signal, gated off with \texttt{rd\_en}. 
$$\texttt{fetch}=\texttt{fetch\_int}\cdot\texttt{rd\_en}$$
